Lesson 2 · 12 min

Step 1: from chat to terminal (OSWork)

The terminal is just another window. With six commands you can walk through your folders; with an AGENTS.md the agent knows who you are and what it may do; with Git you can undo any mistake.

Start the lesson

In this lesson you will

  1. 1Walk through folders in the terminal
  2. 2Write the agent's manual (AGENTS.md)
  3. 3Undo any change with Git
  4. 4Keep keys out of the text

Goal: set up the agent's work folder with rules, a safety net, and secrets kept out of the text.

02 · The work cycle with the agent

Click each step.

1. Ask

Inside the folder, run claude or codex and ask for just one thing, with the result you expect.

Start by asking it to read AGENTS.md: that way it follows your rules.

RequestRead AGENTS.md. Create an index.html with a simple page about me, using what's in there.

2. Run

The agent creates and edits files in the folder. It may ask for permission before running commands.

Your role here is to read what it proposes, not to type for it.

What you seeThe agent creates index.html and explains what it did.

3. Check

Open the result (the page in the browser, the summary, the file) and compare it with what you asked for.

Ask for at least one correction: it's the habit that separates using from managing.

CorrectionChange the title to "HR Consulting" and add a contact section.

4. Save or undo

Like it? git add . and git commit -m "..." save the version.

Don't like it? git restore index.html goes back to what was saved, no panic.

Golden ruleMake a commit before asking for a big change.

03 · The files and commands in the sequence

Copy and use. Replace the text between the < > signs with your own.

Terminal · first folder
mkdir projetos
cd projetos
mkdir meu-primeiro-agente
cd meu-primeiro-agente
dir      # Windows (on Mac and Linux: ls)
AGENTS.md
# Who I am
<your name, your profession, who you work for>

# Rules for this project
- Write in English, short sentences.
- Don't delete files without asking.
- Before finishing, tell me what changed and how I can check it.
- Never write keys or passwords in a text file; they stay in the .env.

# What's in here
- index.html: my page
Terminal · Git and keeping secrets out of the text
git init
echo .env> .gitignore
git add .
git commit -m "primeira versão"

# undo a change made by the agent:
git restore index.html

# the .env must NOT show up here:
git status
Example from the repository
  1. You get to the folder using only the terminal and can say which folder you're in.
  2. AGENTS.md has at least three rules written by you.
  3. The page opens in the browser and you asked for at least one correction.
  4. git status doesn't show the .env.
  • Skipping Git: the agent's first bad change turns into manual rework.
  • Key in AGENTS.md: anything in plain text can end up on GitHub. Keys go only in the .env.
  • Vague request: "improve the page" produces a change you can't check. Ask for a result you can see.

04 · Practice: the 6 exercises of sequence 1

Do them in order. Only move on to the next one when the "done when" is true.

E1 · First folder through the terminal

10 min

Create projetos/meu-primeiro-agente, go into it and list the contents. Open the same folder in Explorer (or Finder) and compare.

Done when: you get to the folder using only the terminal, without the mouse, and can say which folder you're in.

E2 · The employee manual

15 min

Create AGENTS.md with who you are, the project rules, and what's in the folder.

Done when: the file exists and has at least three rules of your own, written by you.

E3 · The first task

15 min

Call the agent and ask it to build the index.html from the AGENTS.md. Open it in the browser and ask for a change.

Done when: the page opens and you asked the agent for at least one fix.

E4 · The safety net

20 min

git init, add and commit. Ask for a big change and, if you don't like it, go back with git restore.

Done when: you undid a change from the agent with one command, no panic.

E5 · Secrets stay out of the text

10 min

Create a .env with a fake key and a .gitignore with the line .env. Add the rule to the AGENTS.md.

Done when: git status does not show the .env.

E6 · The agent reads your files

20 min

Put three of your texts in the folder and ask for a resumo.md with 5 decisions and 5 open items, citing the source of each one.

Done when: you found at least two of the quoted sentences in the original.
