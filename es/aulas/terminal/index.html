Clase 2 · 12 min

Nivel 1: del chat a la terminal (OSWork)

La terminal es solo otra ventana. Con seis comandos te mueves por tus carpetas; con un AGENTS.md el agente sabe quién eres y qué puede hacer; con Git deshaces cualquier error.

Comenzar la clase

En esta clase vas a

  1. 1Moverte por las carpetas desde la terminal
  2. 2Escribir el manual del agente (AGENTS.md)
  3. 3Deshacer cualquier cambio con Git
  4. 4Mantener las claves fuera del texto

Objetivo: armar la carpeta de trabajo del agente con reglas, red de seguridad y secretos fuera del texto.

01 · Cómo se conectan las piezas

Tú das la tarea, el agente trabaja dentro de la carpeta y tú revisas.

  1. 1/5

    Tú

    Tú sigues siendo quien decide: pides, revisas el resultado y aceptas o deshaces. Dar la tarea, revisar y decidir es gestión.

  2. 2/5

    Terminal

    Es por donde llegas a la carpeta y llamas al agente. En Windows, el cmd; en Mac y Linux, la Terminal.

  3. 3/5

    Carpeta del proyecto

    Todo lo que el agente necesita saber está aquí: las reglas en el AGENTS.md, el trabajo en los archivos, las claves en el .env (que Git ignora) y el historial en el .git.

  4. 4/5

    Agente

    El agente lee el AGENTS.md antes de empezar, trabaja en los archivos de la carpeta y, si la regla lo pide, dice qué cambió y cómo lo revisas.

  5. 5/5

    El ciclo completo

    Pides, el agente trabaja dentro de la carpeta siguiendo el AGENTS.md y dice qué cambió. Tú revisas. ¿Te gustó? commit; ¿no te gustó? git restore.

Los mismos archivos sirven para Claude Code y para Codex: los dos leen el AGENTS.md.

02 · El ciclo de trabajo con el agente

Haz clic en cada paso.

1. Pedir

Dentro de la carpeta, llama a claude o codex y pide una sola cosa, con el resultado que esperas.

Empieza pidiéndole que lea el AGENTS.md: así usa tus reglas.

PedidoLee el AGENTS.md. Crea un index.html con una página simple sobre mí, usando lo que está ahí.

2. Ejecutar

El agente crea y edita archivos en la carpeta. Puede pedir permiso antes de ejecutar comandos.

Tu papel aquí es leer lo que él propone, no escribir por él.

Lo que apareceEl agente crea el index.html y explica lo que hizo.

3. Comprobar

Abre el resultado (la página en el navegador, el resumen, el archivo) y compáralo con lo que pediste.

Pide al menos una corrección: es el hábito que separa usar de gestionar.

CorrecciónCambia el título por "Consultoría de RR. HH." y agrega una sección de contacto.

4. Guardar o deshacer

¿Te gustó? git add . y git commit -m "..." guardan la versión.

¿No te gustó? git restore index.html vuelve a lo que estaba guardado, sin pánico.

Regla de oroHaz un commit antes de pedir un cambio grande.

03 · Los archivos y comandos de la secuencia

Copia y usa. Cambia el texto entre los signos < > por el tuyo.

Terminal · primera carpeta
mkdir projetos
cd projetos
mkdir meu-primeiro-agente
cd meu-primeiro-agente
dir      # Windows (no Mac e no Linux: ls)
AGENTS.md
# Quién soy
<tu nombre, tu profesión, para quién trabajas>

# Reglas de este proyecto
- Escribe en español, frases cortas.
- No borres archivos sin preguntar.
- Antes de terminar, di qué cambió y cómo lo reviso.
- Nunca escribas claves ni contraseñas en un archivo de texto; ellas quedan en el .env.

# Qué hay aquí
- index.html: mi página
Terminal · Git y secreto fuera del texto
git init
echo .env> .gitignore
git add .
git commit -m "primeira versão"

# desfazer uma mudança do agente:
git restore index.html

# o .env NÃO pode aparecer aqui:
git status
Ejemplo del repositorio
  1. Llegas a la carpeta solo por el terminal y sabes decir en qué carpeta estás.
  2. El AGENTS.md tiene al menos tres reglas escritas por ti.
  3. La página abre en el navegador y pediste al menos una corrección.
  4. git status no muestra el .env.
  • Saltarse Git: el primer cambio malo del agente se convierte en retrabajo manual.
  • Clave en el AGENTS.md: todo lo que está en texto puede terminar en GitHub. La clave solo va en el .env.
  • Pedido vago: "mejora la página" genera un cambio que no sabes comprobar. Pide un resultado que se pueda ver.

04 · Práctica: los 6 ejercicios de la secuencia 1

Hazlos en orden. Solo pasa al siguiente cuando el "listo cuando" sea verdad.

E1 · Primera carpeta por el terminal

10 min

Crea projetos/meu-primeiro-agente, entra en ella y lista el contenido. Abre la misma carpeta en el Explorador (o Finder) y compara.

Listo cuando: llegas a la carpeta solo por el terminal, sin el mouse, y sabes decir en qué carpeta estás.

E2 · El manual del empleado

15 min

Crea el AGENTS.md con quién eres, las reglas del proyecto y lo que hay en la carpeta.

Listo cuando: el archivo existe y tiene al menos tres reglas tuyas, escritas por ti.

E3 · La primera tarea

15 min

Llama al agente y pídele el index.html a partir del AGENTS.md. Ábrelo en el navegador y pide un cambio.

Listo cuando: la página abre y le pediste al agente al menos una corrección.

E4 · La red de seguridad

20 min

git init, add y commit. Pide un cambio grande y, si no te gusta, vuelve atrás con git restore.

Listo cuando: deshiciste un cambio del agente con un comando, sin pánico.

E5 · El secreto no entra en el texto

10 min

Crea un .env con una clave falsa y un .gitignore con la línea .env. Agrega la regla al AGENTS.md.

Listo cuando: git status no muestra el .env.

E6 · El agente lee tus archivos

20 min

Pon tres textos tuyos en la carpeta y pide un resumo.md con 5 decisiones y 5 pendientes, citando el origen de cada una.

Listo cuando: encontraste en el original al menos dos de las frases citadas.

Ejercicios completos, con el desafío extra (repetir con el otro agente): jornada-agentes/exercicios/01-oswork.md.
